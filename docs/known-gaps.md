# Known gaps before promotion

- `console=ttyS0,115200` ships a serial getty to every install. It is a deliberate VM-test and recovery console for this branch; gate it behind a test build before publishing.
- The image has no NVIDIA variant, application set, agent sandbox, or snapshot automation yet. The README marks these as planned.
- The gaming layer ships Steam and its graphics stack, but no game has been launched from a built image. `ntsync-autoload` arrives as a weak dependency and its kernel module is unverified, and the layer lands on the Intel laptop as well as the gaming machine, because one image serves both.
- The VM test covers the greeter and a serial login. It does not log in through the greeter, start a second session, or exercise the Xfce fallback.
- CI runs the boot test on TCG and does not render or inspect the desktop. The graphical dogfood stays a local pre-promotion step.
- The test disk raises `systemd.default_device_timeout_sec` to 180s so slow TCG boots reach `/boot`. CI therefore cannot catch a regression that only exceeds the shipped 45s.
- `bootc-image-builder` is pinned in `tests/vm/make-disk.sh`, and the base is pinned by digest, but `manifests/packages-common.lock` is a post-build drift gate rather than an install pin. `build/common.sh` installs by name from live repositories, so a third-party rebuild is already in the image when `tests/verify-image.sh` rejects it. The lock covers only the packages the manifest names, so a rebuild of a package they pull in transitively, such as `quickshell` from `duxlabs/dux-repo`, changes the image without failing the gate (#20). The gate also keys on `%{VENDOR}`, a package-controlled string, so a third-party build that declares `Fedora Project` would be skipped. Fedora packages float with the updates repository on every build. Two builds of the same commit can therefore differ (#2).
- The literal base `FROM` removes the `BASE_IMAGE` build argument the candidate-images plan used to build the NVIDIA variant from the same `Containerfile`. That variant needs its own pinned `FROM`, and `tests/test-static.sh` matches `base-main` only, so the NVIDIA image needs a matching assertion before it lands.
- The first-login retry has unit fixtures and a VM marker assertion, but no partial-home VM coverage yet. Rebuild and re-run the graphical dogfood after the retry change.
- The attested SBOM lists packages only. `build/sbom-packages-only.jq` drops the 86111 file entries, the 85109 relationships that point at them, and the package verification codes that covered them, which takes the document from 64181348 to 6508304 bytes. Rekor's public instance answered 502 for the 86 MB DSSE body; a replay reached the service at 16 MB and was rejected at 32 MB. File-level hashes are therefore not attested, and a larger package set could approach the limit again. Every package now reports `filesAnalyzed: false`, because the codes covered a file inventory the document no longer carries.
- `publish` retries signing and attesting for about fifteen minutes per command before it fails, so a permanent error costs that waiting time before the run goes red.
