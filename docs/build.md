# Build

```bash
podman build -t ultus-atomic:dev .
```

The `ctx` stage hands `build/`, `manifests/`, and `overlay/` to one build step, so none of them land in the final image. Packages come from `manifests/packages-common.txt`, one name per line. The desktop hook installs `manifests/packages-desktop.txt`; the server role installs `manifests/packages-server.txt` through `PACKAGE_MANIFEST_EXTRA`. The gaming group pulls in the multilib graphics stack that Steam needs.

The base is pinned in the `Containerfile` as `FROM registry.fedoraproject.org/fedora-bootc:45@sha256:<digest>`. That registry keeps the release images. `quay.io/fedora/fedora-bootc` deletes the previous daily digest about 24 hours after the next `45` build lands, so a clean pull of an older pin fails with `manifest unknown`; the same expiry broke CI on 14 November (#74) and again on 15 November. Fedora signs that image's kernel and modules, so a Secure Boot machine trusts the chain with no per-machine MOK enrollment, and the image carries no desktop environment to strip (#59). A Universal Blue desktop image would inherit both the enrollment machinery and a full KDE or GNOME session; replacing the kernel with one Universal Blue signs (`ublue-os/main/build_files/install.sh:46`) is what forces the enrollment.

The repository provides a scheduled probe workflow (`.github/workflows/repin-base.yml`) that watches this pin and opens a human-reviewed PR to refresh the digest when the registry's tag no longer resolves to the pinned digest; the workflow never merges the change automatically.

Because the base has no desktop, `manifests/packages-common.txt` carries the server-safe base packages, `manifests/packages-desktop.txt` installs the desktop set through the desktop hook, and `manifests/packages-server.txt` adds server-only packages through `PACKAGE_MANIFEST_EXTRA`. The desktop is one module: `manifests/packages-desktop.txt` plus one tree, `modules/desktop/`, which mirrors `/`. `build/common.sh` copies the shared overlay, then every `modules/*/` tree onto `/`, installs the shared manifest through `build/manifest.sh`, and runs every script under `/usr/libexec/ultus-atomic/build.d/` in name order. The desktop ships one such step, `build.d/50-desktop.sh`: it enables the Dux COPRs, installs `manifests/packages-desktop.txt`, applies the first-login user presets, asserts the module's own wiring, disables the COPRs from an exit trap and enables the greeter, so every desktop-specific step travels with the desktop while the shared build knows only the module root and the hook. `tests/test-static.sh` reds when a desktop product name appears in the shared build, the shared manifest, the `Containerfile` or `tests/verify-image.sh`, and `docs/desktop.md` is the swap procedure. The quality-of-life the Universal Blue base provided is restored that way rather than by installing Universal Blue's own packages: `ublue-os-just` exists mainly to enroll the Universal Blue key, and `ublue-setup-services`, `ublue-motd`, and `ublue-os-signing` assume a boot chain this image does not have. `build/common.sh` installs `dnf5-plugins` before any repository work, enables RPM Fusion free and nonfree for the codecs and `steam` (#112), disables `sshd.service` (enabled by default on the Fedora base), while the desktop hook seeds the Flathub remote. Third-party repositories are chosen for maintainer breadth and stability, not convenience: a single-maintainer repository that overrides base packages is the case the rule rejects. The Dux COPRs are the one exception, and not because they are the operator's: they are this image's own desktop environment and deliberately swappable. Updates come from `bootc-fetch-apply-updates.timer`, which the base enables through `86-bootc-standard.preset`. The overlay also replaces `/etc/dnf/dnf.conf`, which the base ships with a comment and `[main]` only, so the image carries `max_parallel_downloads=10`, `fastestmirror=True`, `defaultyes=True`, and an explicit `gpgcheck=True` (#111). The base file holds no other keys to preserve, so replacing it wholesale drops nothing; `gpgcheck=True` is written out rather than inherited. `tests/verify-image.sh` reads the resolved values back with `dnf5 --dump-main-config`, so the assertion is what dnf5 applies rather than the file's text.

The image enables `firewalld`, and the overlay ships `/etc/firewalld/zones/public.xml` with `ssh` and `dhcpv6-client` only (#116). The distribution's public zone also allows `mdns`, which advertises the host on the local network, so this file narrows the baseline rather than copying it. Opening `http`, `https`, or `mdns` is an operator decision that this file does not make, and `tests/test-static.sh` reds if one appears without that decision. `tests/verify-image.sh` asserts the effective set with `firewall-offline-cmd --zone=public --list-services`, so a zone file that parses but is not applied reds.

The pin is literal rather than a build argument, so the `FROM` line states the digest a reader audits. `tests/test-static.sh` asserts the tag+digest form, rejects a returning `ARG BASE_IMAGE`, and requires every `FROM` line to be either `scratch` or a tag+digest pin, so the NVIDIA variant's own base in #95 is covered too. `repin-base.yml` is the only path that refreshes the pin: Dependabot's docker ecosystem cannot read `registry.fedoraproject.org` and fails every run with `private_source_authentication_failure` (run 44125441096), so `.github/dependabot.yml` carries no docker entry and the scheduled probe is the drift signal (#102).

`manifests/packages-common.lock` records the NEVRA and the package `%{from_repo}` for every installed package whose origin repository is not a Fedora repository, one line per NEVRA; a multilib name such as `mangohud` contributes two lines. The recorded origins are the Dux COPRs and the RPM Fusion ids `rpmfusion-free`, `rpmfusion-free-updates`, `rpmfusion-nonfree` and `rpmfusion-nonfree-updates` (#112), plus `@commandline` for the two RPM Fusion release packages, which the build installs from a local file; their NEVRA pins the release package, so a new release reds the gate like any other third-party rebuild. The generator normalizes a COPR project's dependency repository id (`coprdep:`) to the project's main repository id (`copr:`) because which repository served a package can vary at build time; the NEVRA still pins what landed and such a move between the two COPR repos is not considered drift. It is a drift gate, not an install pin: the build installs by name from live repositories, and the gate compares the recorded set against the image afterwards. `tests/verify-image.sh` compares the whole recorded set to the generator's measurement (the generator drops `+git` builds), so an unpinned third-party rebuild — including a transitive one — is caught. `tests/test-lock-drift.sh` runs the same comparison from `build/compare-lock.sh` without an image. Fedora-origin packages are excluded so a Fedora updates bump does not red the gate. Run `just lock` after changing the manifest, and whenever the gate reports third-party drift, whether a base bump or a COPR rebuild.

`tests/verify-image.sh` runs `bootc container lint`, `systemd-analyze verify`, the package assertions, and the lock comparison against a built image. `just build` and `just lint-image` wrap the build and the verification.

CI builds the same image and turns it into a qcow2 with bootc-image-builder. See [CI](ci.md) and [Testing](testing.md).
