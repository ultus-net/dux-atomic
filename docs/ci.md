# CI and publishing

`.github/workflows/ci.yml` runs on every pull request, every push to `main`, and manual dispatch. Every action is pinned to a commit SHA, and the job that runs PR code holds only `contents: read`.

- `static` runs `tests/lint.sh`: shell syntax, shellcheck, hadolint, actionlint, and `tests/test-static.sh`. The script pins the linter images by digest. `tests/test-static.sh` also asserts the base pin's tag+digest form, rejects a returning `ARG BASE_IMAGE`, and checks the package lock's header, `<nevra> TAB <vendor>` format, and ordering. `just check` runs the same script.
- `image` builds the image, runs `tests/verify-image.sh` (`bootc container lint`, `systemd-analyze verify`, the package assertions, and the third-party lock comparison), generates an SPDX SBOM with syft, trims it with `build/sbom-packages-only.jq` so the attestation fits Rekor's request limit, builds the qcow2 with bootc-image-builder, and runs `boot-smoke.sh` on QEMU TCG with a 900s boot timeout and a 300s `greetd` grace. The boot test asserts the greeter session through `loginctl` after a serial login, not rendered pixels. It then scans with a digest-pinned trivy container and uploads the report. The scan is report-only until the Fedora base findings are triaged (#3).
- `publish` runs only on `main`, holds the write token and OIDC identity, and runs no repository code. It loads the built artifact, pushes `:sha-<commit>`, signs the digest with cosign keyless OIDC, attests the SBOM, and verifies both the signature and the attestation. Signing and attesting each retry up to five times with a 30s pause that doubles to 240s, each attempt is capped at five minutes, and each command gets a ten-minute budget, so a genuine 5xx or network failure rarely fails the only publish path while a stalled connection still ends with a message inside the job's 60 minutes. The two verification calls are single-shot and capped at three minutes each, so a slow verification reds the run and a human retries. The pushed digest is emitted as a check-run annotation before signing, so the digest is recorded even when a timed-out job keeps no log. `:latest` never moves on a red publish.
- A `workflow_dispatch` on `main` with `promote` set copies the signed manifest to `:latest` and asserts the registry digest. A failed copy leaves the previous tag and fails the run, so a human retries. A push never moves `:latest`.
- A `workflow_dispatch` on `main` with `publish` set and `promote` unset publishes the commit it runs on without moving `:latest`. A dispatch with neither input runs only `static` and `image`, so a green run does not always publish.
- `static` and `image` are required checks on `main`; a red hosted `image` run blocks merge.
- The `ghcr` environment is the approval hook. Add required reviewers in the repository settings to gate publication.
- The first push creates a private GHCR package. Set the package visibility to public in the package settings if anonymous pulls are wanted.

The SBOM step scans a flattened rootfs with a digest-pinned syft container. syft needed more than 8 GB to scan the docker archive, so the step exports the image first, and it writes the report to a file rather than buffering it in memory.

`just check` mirrors the static gate. `just build`, `just lint-image`, `just disk`, and `just boot` cover the rest.
