# CI and publishing

`.github/workflows/ci.yml` runs on every pull request, every push to `main`, and manual dispatch. Every action is pinned to a commit SHA, and the job that runs PR code holds only `contents: read`.

- `static` runs `tests/lint.sh`: shell syntax, shellcheck, hadolint, actionlint, and `tests/test-static.sh`. The script pins the linter images by digest. `tests/test-static.sh` also asserts the base pin's tag+digest form, rejects a returning `ARG BASE_IMAGE`, and checks the package lock's header, `<nevra> TAB <vendor>` format, and ordering. `just check` runs the same script.
- `image` builds the image, runs `tests/verify-image.sh` (`bootc container lint`, `systemd-analyze verify`, the package assertions, and the third-party lock comparison), generates an SPDX SBOM with syft, trims it with `build/sbom-packages-only.jq` so the attestation fits Rekor's request limit, builds the qcow2 with bootc-image-builder, and runs `boot-smoke.sh` on QEMU TCG with a 900s boot timeout and a 300s `greetd` grace. The boot test asserts the greeter session through `loginctl` after a serial login, not rendered pixels. It then scans with a digest-pinned trivy container, and the scan is blocking: `.trivyignore` holds the triaged findings in the duxlabs Go binaries and the base image's `sysroot/ostree/repo/objects` copies, each with an expiry date and the fixed upstream version beside its group, so a new finding or an expired entry reds `image`. The report uploads even when the scan fails, so the evidence survives (#3).
- `publish` runs only on `main`, holds the write token and OIDC identity, and runs no repository code. It loads the built artifact, pushes `:sha-<commit>`, signs the digest with cosign keyless OIDC, attests the SBOM. A first step writes the `with_log` and `retry` helpers to `$RUNNER_TEMP/helpers.sh`, and each signing step sources that file and runs its own bounded commands, so a hang names the step it came from. Signing and attesting each retry up to five times with a 30s pause that doubles to 240s, each attempt is capped at five minutes, and each command gets a ten-minute budget, so a genuine 5xx or network failure rarely fails the only publish path while a stalled connection still ends with a message inside the job's 60 minutes. Sign and attest carry their own `timeout-minutes: 15`: run 42933898962 was cancelled by the job's 60-minute cap without firing the single step's 40-minute bound, and run 42943634705 ran 51 minutes past it, so the work is split instead of trusted to one step bound. The pushed digest is emitted as a check-run annotation by its own step immediately after the tag push, before any signing, so the digest is recorded even when a timed-out job keeps no log. Each signing command writes its output to a file under `$RUNNER_TEMP` and the file is printed after the command returns, likely because a cosign child that outlives its `timeout` inherits the step's stdout pipe and the runner waits for that pipe to close. A final `if: always()` step uploads `$RUNNER_TEMP/*.log` as the `publish-logs` artifact, so the steps that ran keep their logs when a later one dies. A job that reaches its own 60-minute cap still drops the pending upload, which is the path every hung run has taken so far (#26).
- `verify` runs after `publish` with only `contents: read` and `packages: read`, and holds no OIDC identity. It logs in to GHCR, installs the same cosign version `publish` pins, and runs `cosign verify` and `cosign verify-attestation` against the digest `publish` exports, each under a three-minute `timeout --kill-after` and an eight-minute step bound. The job carries `timeout-minutes: 20`, because a stall here survived both a command timeout and a step timeout: run 42961488922 signed in 4s and attested in 5s, then held the combined verification step from 05:32:56 to the job's 60-minute cap without a log or an annotation. Only a job boundary ends a process in uninterruptible wait, and moving it out keeps `publish` green so the main queue drains. A red `verify` still blocks `:latest`.
- `promote` runs only on a `workflow_dispatch` on `main` with `promote` set, and needs both `publish` and `verify`. It copies the signed manifest to `:latest` and asserts the registry digest. A failed copy leaves the previous tag and fails the run, so a human retries. A push never moves `:latest`.
- A `workflow_dispatch` on `main` with `publish` set and `promote` unset publishes the commit it runs on without moving `:latest`. A dispatch with neither input runs only `static` and `image`, so a green run does not always publish.
- `static` and `image` are required checks on `main`; a red hosted `image` run blocks merge.
- The `ghcr` environment is the approval hook. Add required reviewers in the repository settings to gate publication.
- The first push creates a private GHCR package. Set the package visibility to public in the package settings if anonymous pulls are wanted.

The SBOM step scans a flattened rootfs with a digest-pinned syft container. syft needed more than 8 GB to scan the docker archive, so the step exports the image first, and it writes the report to a file rather than buffering it in memory.

`just check` mirrors the static gate. `just build`, `just lint-image`, `just disk`, and `just boot` cover the rest.
