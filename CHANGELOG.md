# Changelog

## Unreleased

- Add the CI/CD pipeline. `.github/workflows/ci.yml` runs shell syntax, shellcheck, `tests/test-static.sh`, and hadolint on every PR; builds the image, runs `bootc container lint` and `systemd-analyze verify`, emits an SPDX SBOM with syft, scans with trivy, builds the qcow2 with bootc-image-builder, and runs `boot-smoke.sh` on QEMU TCG. On `main` it pushes `ghcr.io/ultus-net/dux-atomic:latest` and `:sha-<commit>`, signs the digest with cosign keyless OIDC, and attests the SBOM. `boot-smoke.sh` falls back to TCG when `/dev/kvm` is absent and finds Ubuntu's OVMF paths. `make-disk.sh` passes the SELinux label only on an SELinux host. Add `justfile` for local parity, `LICENSE` (MIT), and Dependabot for the actions.
- Apply the final review fixes. `needs-setup.sh` derives the marker from `${XDG_STATE_HOME:-$HOME/.local/state}`, matching the unit's `%S`, so a home that sets `XDG_STATE_HOME` no longer re-runs setup every login. `boot-smoke.sh` asserts `DUX_SETUP_MARKER` and says `graphical.target` is unverified when the fallback path is taken. `build/common.sh` fails on an unreadable package manifest instead of treating it as empty. `test-static.sh` treats a condition-script crash as a failure, uses a real dms config line with provenance, and adds an `XDG_STATE_HOME` fixture. The greeter seed creates its state directory at mode 0750 to match the package rule. The README states the desktop retry's failure contract and its absent attempt cap.
- Record the pre-promotion gaps in the README and mark the serial console karg as a gate. `README.md` lists the shipped serial getty, missing CI, license, NVIDIA variant, application set, agent sandbox, snapshot automation, greeter-login and Xfce VM coverage, floating base tag, unpinned COPR packages, and the untested first-login retry. The `console=ttyS0,115200` comment in `overlay/usr/lib/bootc/kargs.d/10-console.toml` says it is a test and recovery console to gate before publishing.
- Retry a partial first login. `dux-atomic-desktop.service` replaces the `config.kdl` condition with `ExecCondition=/usr/libexec/dux-atomic/needs-setup.sh`: it runs the setup for a fresh home or a dms-generated config without `${XDG_STATE_HOME:-$HOME/.local/state}/dux-atomic/desktop-setup.done`, and skips a user-authored config. `ExecStartPost` writes the marker only after `dms setup` exits 0, so a failed or timed-out run retries on the next login. `tests/test-static.sh` runs the six condition fixtures and fails if the retry or skip logic regresses.
- Apply the adversarial review fixes. `boot-smoke.sh` fails when the login shell prompt never appears instead of sending probes with `|| true`. `make-disk.sh` pins the bootc-image-builder manifest by digest and drops `--pull=newer`, with `BIB_IMAGE` to override the pin. `.dockerignore` keeps `.git`, `.vm`, `output`, `docs`, and `tests` out of the build context. README separates shipped components from planned ones: the NVIDIA variant, the application set, signed publication, agent containers, and home snapshots are planned, not present.
- Close the open P2/P3 review follow-ups. `boot-smoke.sh` waits for the `printf`-emitted `DUX_USER:<name>` and `DUX_PROBE_END:ok` markers, so an echoed command cannot satisfy a probe wait. `build/common.sh` asserts the greeter portal mask points at `/dev/null` and traps the tmpfiles scratch root on every exit. The tmpfiles rule states why the greeter home keeps mode 0755, and the design spec says one notification daemon per session and names the CI workflow as image-repo ownership. `test-static.sh` fails if the echoed waits or the mask assertion regress.
- Confirm the first-login desktop end to end on image `3e886bc33a30`: a pristine GL boot of the `make-disk.sh` candidate showed the greeter with the niri session preselected, logged in as the test account through the user picker, and reached `niri.service` and `dms.service` active with the DMS bar and Welcome dialog rendered. No manual `dms setup` ran. The run is recorded in `docs/research/2026-11-10-dms-first-login.md`; the screenshots stay in the ignored `.vm/` tree.
- Provision the Dux desktop for a new account on its first graphical login: `dux-atomic-desktop.service` runs `dms setup headless --compositor niri --terminal ghostty --skip-existing` at `graphical-session-pre.target` unless the user already owns a niri config, and `dux-atomic-dms-defaults.service` seeds a dark DMS session background. A user preset enables both units, an image-level `niri.service.wants/dms.service` starts the shell on the first login, and both units skip root and the greeter. `boot-smoke.sh` starts the units after the console login and asserts the provisioned files and the image-level binding. The DMS session schema and setup contract are recorded in `docs/research/2026-11-10-dms-first-login.md`. The greeter keeps the upstream `dms-greeter --command niri` config because Fedora's greetd 0.10.3 does not ship a `greetd-spawn` binary. `dux-atomic-greeter-defaults.service` seeds the greeter memory with `lastSessionDesktopId: "niri.desktop"` before `greetd.service`, because the greeter otherwise picks a nondeterministic session index from the asynchronous desktop-file load order.
