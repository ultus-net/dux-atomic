# Changelog

## Unreleased

- Prove the signature policy accepts and rejects with a fixture key (#4). `tests/test-signing.sh` generates a throwaway keypair with `cosign generate-key-pair`, runs a digest-pinned `registry:2` on `127.0.0.1:5000`, pushes two digest-pinned images as `:signed` and `:unsigned`, signs `:signed` with `--allow-insecure-registry`, and runs `skopeo copy` four times under a fixture `sigstoreSigned` policy whose `keyPath` is the fixture public key and whose `signedIdentity` is `matchRepository`. An exact tag match is wrong because cosign writes the repository, not the tag, into the signature payload. A fixture `registries.d` file sets `use-sigstore-attachments: true` for the local registry, without which `containers/image` looks in a local lookaside directory and reports no signature, so every case would reject for the wrong reason. The signed tag and the signed digest are accepted, and the unsigned tag and a signature from an untrusted key are rejected. The two tags carry different digests because a signature attaches to the digest, so a second tag on the same digest inherits it and cannot exercise rejection. `tests/lint.sh` shellchecks the script without running it, `.github/workflows/ci.yml` gains a `signing` job after `static` that installs podman, skopeo and the cosign v2.6.5 that `publish` pins, and `just signing` runs it locally. The shipped policy is deferred, so the work item stays open: `sigstoreSigned.fulcio` matches only x509 email SANs while a GitHub Actions certificate carries the workflow as a URI SAN, so a keyless policy cannot name this workflow and a shipped policy needs a release key plus rotation. `docs/known-gaps.md` records the gap and cites `container-libs#388`.

The step also carries its own 40-minute `timeout-minutes`, so the bound holds whatever the cause. `tests/test-static.sh` fails when any of the four calls stops being wrapped, when the read is unbounded, when the cut is not ignored, or when the status is dropped, and it runs the helper to prove it prints output and returns the command's own exit status.

- Leave `+git` builds out of the package lock and its drift gate. The duxlabs COPR submitted `dux-greeter-git` as `git132.7bdf4546` at 20:26:05Z and as `git133.83f318bf` at 21:13:54Z, so every open pull request failed the gate on a NEVRA that no commit could have recorded (`42907280152`, `42907296213`, `42907323441`). A git snapshot tracks an upstream branch and cannot be pinned, so `build/package-lock.sh` now drops it (`awk '!index($0, "+git")'`), `tests/verify-image.sh` filters it from both sides, and `manifests/packages-common.lock` no longer carries the greeter line. The VM boot test is the coverage that a broken greeter build cannot hide behind the missing lock line. `tests/test-static.sh` counts the filter on both comparison sides and checks the generator's `sort -u | awk` pipeline, so deleting either side fails the static gate. `docs/build.md` and `docs/known-gaps.md` record the exclusion.
- Bound the publish signing and attestation retries. Run 42827200322 pushed `:sha-133fa04`, then sat in "Sign the digest and attest the SBOM" for 51 minutes until the 60-minute job timeout killed it, and GitHub kept no log for the timed-out job, so nothing could say which call hung. Each attempt now runs under a five-minute `timeout --kill-after`, and each command has a ten-minute wall-clock budget over at most five attempts, so the step is bounded even when every call hangs, and a stall ends with a message instead of a killed job. The two verification calls are single-shot and capped at three minutes each. The step emits the pushed digest as a check-run annotation before signing. `tests/test-static.sh` fails if the cap, the budget, the failure return, the attempt counter, or the notice ordering is removed, and it runs the helper itself at scaled constants to prove a hang is cut.
- Pin the base image and lock the manifest-named third-party packages (#2). The `Containerfile` now builds `FROM ghcr.io/ublue-os/base-main:45@sha256:444e9e37ea581e76829772ae2a42edfdbacdd0cbc7a27085a4ed0f3d6e1336c7`, and the `BASE_IMAGE` build argument and its hadolint suppression are gone. The pin is literal because Dependabot's docker ecosystem fetches any file whose name matches `containerfile|dockerfile` (the fetcher's `DOCKER_REGEXP` is `/dockerfile|containerfile/i`) and never expands an `ARG` into `FROM`; `.github/dependabot.yml` gains a `docker` entry, so a same-tag digest bump reaches the repo as a pull request unless the digest-only-update suppression experiment is on. `manifests/packages-common.lock` records the resolved NEVRA and vendor of every manifest name that is not a `+git` build, one line per NEVRA, measured in a built image, and `build/package-lock.sh` plus `just lock` regenerate it atomically from an image whose rpm database is the source of truth. The lock is a post-build drift gate, not an install pin: the build installs by name from live repositories and `tests/verify-image.sh` rejects the result afterwards. It fails when a line whose vendor is not `Fedora Project` drifts, which covers the unpinned COPR and `negativo17` builds; Fedora lines are excluded because they move with the updates repository on every build. Packages the manifest names pull in transitively stay outside the lock, and `docs/known-gaps.md` records that gap (#20), the package-controlled `%{VENDOR}` filter, and the NVIDIA variant's need for its own pinned `FROM`. `tests/test-static.sh` asserts the tag+digest form, rejects a returning `ARG BASE_IMAGE`, fails on an unpinned base `FROM`, and checks the lock's header, `<nevra> TAB <vendor>` format, and ordering. The first drift bump landed in the same pull request: the duxlabs COPR rebuilt `dux-greeter-git` from `git131.399eb7fa` to `git132.7bdf4546`, the gate printed that NEVRA diff on run 42895376976, and the lock recorded git132 until the `+git` exclusion above removed the greeter line.
